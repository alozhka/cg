# Алгоритм Моллера–Трумбора (пересечение луч–треугольник)

Реализация: `src/core/RayMesh.hpp`, метод `IntersectRayTriangle` (строки 139–174).

## Постановка уравнения

Точка на луче: `O + t·D`. Точка на треугольнике в барицентрических координатах:

```
P = (1−u−v)·V0 + u·V1 + v·V2  =  V0 + u·E1 + v·E2
```

где:
- `E1 = V1 − V0` (`edge1`, строка 146)
- `E2 = V2 − V0` (`edge2`, строка 147)

Приравниваем луч и треугольник и переносим неизвестные (`t, u, v`) влево:

```
O + t·D = V0 + u·E1 + v·E2
−t·D + u·E1 + v·E2 = O − V0 = T
```

Это система из 3 уравнений (по x, y, z) с 3 неизвестными. В матричном виде:

```
[ −D | E1 | E2 ] · [t, u, v]ᵀ = T,   где T = O − V0  (tvec, строка 157)
```

## Решение по правилу Крамера

Определитель матрицы из трёх векторов-столбцов — это смешанное произведение
(scalar triple product):

```
det[a|b|c] = a · (b × c)
```

### Знаменатель

```
det = −D · (E1 × E2) = E1 · (D × E2)
```

(перестановка в смешанном произведении). Отсюда `pvec`:

```cpp
pvec = cross(D, E2);     // D × E2          (строка 149)
det  = dot(E1, pvec);    // E1 · (D × E2)   (строка 150) ← знаменатель Крамера
```

**Что такое `pvec` геометрически:** вектор `D × E2`, перпендикулярный направлению
луча и ребру E2. Это вспомогательный вектор для смешанного произведения,
**а не нормаль треугольника**. Нормаль треугольника была бы `E1 × E2` — это разные вещи.

### Проверка `det ≈ 0`

`det = E1·(D×E2)` обращается в ноль, когда три вектора `−D, E1, E2` компланарны —
то есть **луч лежит в плоскости треугольника (параллелен ей)**. Тогда пересечения
нет (или их бесконечно много — вырожденный случай).

```cpp
if (IsParallelToTriangle(det)) return std::nullopt;   // строки 151, 176–179
// std::abs(det) < PARALLEL_EPS,  PARALLEL_EPS = 1e-7
```

### Числители

`invDet = 1/det` считаем один раз — три умножения вместо трёх делений (быстрее).

По Крамеру для каждой неизвестной заменяем соответствующий столбец на правую
часть `T`. После раскрытия смешанных произведений все три числителя выражаются
через два переиспользуемых векторных произведения `pvec` и `qvec`:

```cpp
qvec = cross(tvec, edge1);          // Q = T × E1   (строка 158)

u = dot(tvec, pvec) * invDet;       // (T · pvec) / det   (строка 160)
v = dot(D,    qvec) * invDet;       // (D · qvec) / det   (строка 161)
t = dot(edge2, qvec) * invDet;      // (E2 · qvec) / det  (строка 167)
```

В этом красота алгоритма: всего **2 cross + несколько dot** на треугольник.

## Проверки попадания

### Внутри ли треугольника

```cpp
IsInsideTriangle: u >= 0 && v >= 0 && u + v <= 1   // строки 181–184
```

Барицентрические координаты внутри треугольника неотрицательны и в сумме ≤ 1.
Если `u<0`, `v<0` или `u+v>1` — точка пересечения с плоскостью есть, но она вне
треугольника.

### Валидность параметра t

```cpp
if (t < MIN_T || t >= maxT) return std::nullopt;   // строка 168
```

- `t < MIN_T` — пересечение позади камеры или слишком близко (отсекаем
  self-intersection и артефакты, `MIN_T = 1e-4`).
- `t >= maxT` — уже нашли треугольник ближе. В цикле по треугольникам
  (`Intersect`, строка 101) после каждого попадания `tMax = hit->t`, поэтому
  в итоге остаётся **ближайший** треугольник.

## Итоговые формулы

```
       D × E2 = pvec          T × E1 = qvec          T = O − V0

det = E1 · pvec
u   = (T  · pvec) / det
v   = (D  · qvec) / det
t   = (E2 · qvec) / det
```

Всё это — прямое решение системы `[−D|E1|E2]·[t,u,v]ᵀ = T` по Крамеру с хитрым
переиспользованием смешанных произведений.

**Геометрический смысл:** находим, в какой точке луч протыкает плоскость
треугольника (`t`), и где эта точка в координатах рёбер (`u, v`); если `u, v`
валидны — попали. Дальше `u, v` используются для интерполяции нормали
(`InterpolatedNormal`, строки 108–113, сглаживание по Фонгу).
