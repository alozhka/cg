# Пересечение луча с AABB (slab method)

Реализация: `lw8/ray_tracing/src/core/AABB.hpp`, метод `Intersect` (строки 31–40).

## Что такое AABB

**A**xis-**A**ligned **B**ounding **B**ox — прямоугольный параллелепипед, рёбра
которого параллельны осям координат. Полностью задаётся двумя точками: `m_min`
(минимальный угол) и `m_max` (максимальный угол). Это «коробка» вокруг объекта
(например, вокруг меша), которой пользуются для быстрого отсечения: если луч
не попал в коробку — точно не попал в меш внутри, можно не проверять треугольники.

## Идея метода: пересечение трёх «плит»

AABB можно представить как пересечение трёх **плит** (slabs) — бесконечных полос
между парой параллельных плоскостей:

- X-плита: `m_min.x ≤ x ≤ m_max.x`
- Y-плита: `m_min.y ≤ y ≤ m_max.y`
- Z-плита: `m_min.z ≤ z ≤ m_max.z`

Точка лежит внутри коробки ⇔ она внутри всех трёх плит одновременно.

Для каждой плиты считаем **интервал** `[tNear_axis, tFar_axis]` параметра `t`,
при котором луч находится между плоскостями этой оси. Луч пересекает коробку ⇔
**пересечение всех трёх интервалов непусто**.

## Что такое «интервал параметра t» — на примере

Точка на луче: `P(t) = O + t·D`. Параметр `t` — это «время» вдоль луча: при `t=0`
мы в начале `O`, при `t=1` сместились на вектор `D`, при `t=2` — на `2·D`, и так далее.
Отрицательные `t` — позади начала луча.

Пусть `O = (0, 0, 0)`, `D = (1, 0, 0)` (луч ползёт вдоль оси X), а коробка —
`m_min = (3, −1, −1)`, `m_max = (5, 1, 1)`.

**Ось X.** Луч пересекает плоскость `x = 3` в `t = 3`, плоскость `x = 5` в `t = 5`.
Значит **по X** луч находится внутри плиты при `t ∈ [3, 5]`. Это и есть
`[tNear_x, tFar_x]`. До `t=3` — луч ещё слева от коробки; между 3 и 5 — внутри
X-плиты; после `t=5` — справа от коробки.

**Ось Y.** Луч имеет `D.y = 0` — он вообще не движется по Y, всё время сидит на
`y = 0`. А плита по Y — это `−1 ≤ y ≤ 1`, и `0` туда попадает **всегда**. Значит
по Y интервал — `(−∞, +∞)`. Эта ось не ограничивает.

**Ось Z.** Аналогично Y: `[tNear_z, tFar_z] = (−∞, +∞)`.

**Пересечение:** `[3, 5] ∩ (−∞, +∞) ∩ (−∞, +∞) = [3, 5]`. То есть луч находится
внутри коробки при `t ∈ [3, 5]` — входит в `t=3`, выходит в `t=5`. Это и есть
финальный ответ: `tNear = 3`, `tFar = 5`.

### Случай «мимо»

Та же коробка, но `O = (0, 5, 0)`, `D = (1, 0, 0)`. Теперь луч идёт на высоте
`y = 5`, а Y-плита коробки — `[−1, 1]`. Y-плиту луч не пересекает никогда:

- по X: `t ∈ [3, 5]` как раньше;
- по Y: `D.y = 0`, `O.y = 5` снаружи плиты — интервал **пустой** (в коде он
  получится как `[+∞, +∞]` или `[−∞, −∞]`, см. ниже про деление на ноль);
- пересечение с пустым — пусто. `tNear > tFar`, возвращается `false`.

### Случай «луч идёт под углом»

`O = (0, 0, 0)`, `D = (1, 1, 0)`, коробка та же `[3,5] × [−1,1] × [−1,1]`.

- X-плита: `t ∈ [3, 5]` (как раньше).
- Y-плита: пересечения с `y = −1` в `t = −1`, с `y = 1` в `t = 1`. Интервал `[−1, 1]`.
- Z-плита: `(−∞, +∞)`.

Пересечение `[3, 5] ∩ [−1, 1] = ∅` — `tNear = 3`, `tFar = 1`, `3 > 1`, мимо. Луч
по диагонали успевает выйти из Y-плиты (в `t=1`, в точке `(1, 1, 0)`) задолго до
того, как добрался бы до X-плиты (в `t=3`).

Это и есть геометрический смысл «пересечения интервалов»: коробку увидели тогда
и только тогда, когда **существует такое `t`, при котором луч одновременно
внутри всех трёх плит**.

## Вход в плиту и выход из неё (код)

Чтобы найти, при каком `t` луч пересекает плоскость `x = m_min.x`, решаем:

```
O.x + t·D.x = m_min.x
t = (m_min.x − O.x) / D.x
```

Аналогично для `x = m_max.x`. То же по `y` и `z`. В коде всё это делается
**сразу для трёх осей** через векторные операции:

```cpp
const glm::vec3 invDirection = 1.0f / ray.direction;        // строка 33
const glm::vec3 t0 = (m_min - ray.origin) * invDirection;   // строка 34
const glm::vec3 t1 = (m_max - ray.origin) * invDirection;   // строка 35
```

- `invDirection` — покомпонентно `(1/Dx, 1/Dy, 1/Dz)`. Считаем обратное один раз,
  дальше **умножаем** (как в Моллере–Трумборе — деление дороже умножения).
- `t0` — три значения параметра, при которых луч пересекает плоскости **`m_min`**
  по каждой оси.
- `t1` — то же для плоскостей **`m_max`**.

Но `t0[i]` — это **не обязательно** вход в i-ю плиту. Если `D.x > 0`, луч сначала
пересечёт `x = m_min.x` (вход), потом `x = m_max.x` (выход). А если `D.x < 0`,
всё наоборот — сначала `m_max.x`, потом `m_min.x`. Деление на отрицательное
число «переворачивает» порядок.

Поэтому для каждой оси:

```
tNear_axis = min(t0[i], t1[i])   // вход в плиту (раньше)
tFar_axis  = max(t0[i], t1[i])   // выход из плиты (позже)
```

`glm::min(t0, t1)` / `glm::max(t0, t1)` делают это **покомпонентно** сразу по
всем трём осям — никаких ветвлений по знаку `D`, никаких `if (D.x > 0)`.

## Пересечение трёх интервалов

Точка внутри коробки ⇔ внутри всех плит одновременно ⇔ `t` лежит во всех трёх
интервалах `[tNear_i, tFar_i]` сразу. Пересечение интервалов:

```
tNear = max(tNear_x, tNear_y, tNear_z)   // самый поздний вход
tFar  = min(tFar_x,  tFar_y,  tFar_z)    // самый ранний выход
```

Это делают `glm::compMax` / `glm::compMin` — «horizontal» редукции по 3
компонентам вектора:

```cpp
tNear = std::max(tMin, glm::compMax(glm::min(t0, t1)));   // строка 37
tFar  = std::min(tMax, glm::compMin(glm::max(t0, t1)));   // строка 38
```

Дополнительно зажимаем интервал в **окно** `[tMin, tMax]`, переданное снаружи:
- `tMin` обычно `0` (отсекаем то, что позади камеры);
- `tMax` — расстояние до уже найденного ближайшего пересечения (если луч и так
  упирается в более близкий треугольник, дальше нет смысла лезть в эту коробку).

## Условие попадания

```cpp
return tNear <= tFar;   // строка 39
```

- `tNear > tFar` — интервалы плит **не пересекаются**, луч мимо коробки.
- `tNear ≤ tFar` — есть общий промежуток параметра, луч проходит сквозь коробку.
  Сам отрезок `[tNear, tFar]` — это интервал параметра, на котором луч находится
  **внутри** AABB.

Если луч начинается внутри коробки, получится `tNear < 0 < tFar` — после клампа
`max(tMin=0, …)` придёт `tNear = 0`, что корректно: луч уже внутри с самого начала.

## Почему это работает с `D.x = 0`

Если `D.x = 0`, луч параллелен плитам по X, и `invDirection.x = ±inf` (IEEE-754
деление). Тогда:
- если `O.x` внутри `[m_min.x, m_max.x]`: `(m_min.x − O.x)` имеет один знак,
  `(m_max.x − O.x)` — другой, после умножения на `±inf` получаем `−inf` и `+inf`.
  После `min/max`: `tNear_x = −inf`, `tFar_x = +inf` — эта ось «не ограничивает»,
  что и нужно: луч в X-плите при любом `t`.
- если `O.x` снаружи плиты: оба `(m_min.x − O.x)` и `(m_max.x − O.x)` одного
  знака, после `±inf` получаем `+inf, +inf` или `−inf, −inf`, и пересечение с
  `[tMin, tMax]` будет пустым — корректно, луч плиту не пересекает никогда.

Поэтому в коде нет специальных проверок `D.i == 0` — IEEE-арифметика сама даёт
правильный ответ. (Тонкий момент: `0 / 0 = NaN` сломает это, но
`(m_min.x − O.x)` равно нулю только когда `O.x` точно на плоскости — на практике
редко и обычно безопасно.)

## Перегрузка без `tNear`/`tFar`

```cpp
bool Intersect(const Ray& ray, float tMax) const   // строки 42–47
{
    float tNear = 0.f;
    float tFar = 0.f;
    return Intersect(ray, 0, tMax, tNear, tFar);
}
```

Удобная обёртка для случая «нужен только факт пересечения, без точек входа/выхода».
Используется, например, в BVH: «есть ли смысл лезть в этот узел?»

## `Grow`

```cpp
void Grow(const glm::vec3& p)   // строки 25–29
{
    m_min = glm::min(m_min, p);
    m_max = glm::max(m_max, p);
}
```

Расширяет коробку, чтобы она охватила точку `p`. Стартовая инициализация:

```cpp
glm::vec3 m_min{ +inf };
glm::vec3 m_max{ −inf };
```

— **намеренно «перевёрнутая» пустая** коробка. Любая `Grow(p)` сразу выставит
`min ≤ max`, потому что `min(+inf, p.x) = p.x` и `max(−inf, p.x) = p.x`. Это
классический трюк: не нужно отдельной ветки «первая точка» — пустая AABB просто
естественно превращается в нормальную после первого `Grow`.

## Итоговая идея в одной строке

```
[tNear, tFar] = [tMin, tMax] ∩ ⋂_axis [min(t0_axis, t1_axis), max(t0_axis, t1_axis)]
                                                                     ↑ если пусто — мимо
```

— шесть пересечений плоскостей, шесть min/max, одно сравнение. Никаких
ветвлений, всё векторизуется.
